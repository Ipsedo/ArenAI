**Three facts from the analysis (back-of-envelope model, to verify on a run):**
1. A shortage cannot teach anything to an agent whose p(hit) does not depend on state: keeping a shell = waiting for a better shot, which does not exist for it; and any fire cost that would bite extinguishes the trigger (345/465/471). So scarcity must **follow** competence, not precede it.
2. Refund k per hit: spam is self-financed as soon as p·k ≥ 1. At blind p 5-7 % and k = 20 (474), the reserve is infinite while density holds ⟹ permanent dump of 474. Need k < 1/p_blind ≈ 14 **eventually**, but k ≈ 20 at start = regen equivalent.
3. γ 0.99 at 10 Hz: keeping a shell for an aligned+close shot (50 %, visited ~1 time/8 s) is worth 0.15·Σγ^{80i}. N = 30: dump 0.5 vs keep 0.27 (0.99) / 0.45 (0.995) / 0.70 (0.997). N = 8: dump 0.15 vs 0.27 / 0.44 / 0.6. ⟹ small reserve **and** γ ≥ 0.995.
Corollaries: the 8-9 % hit ceiling of the regen era is the signature of « always fires » (1.2 % aligned+close shots at 50 %), not an aim ceiling; the spawn-curriculum threshold 0.06 is the chance level at 32 tanks, D advances on luck.

**Proposal:** event reward unchanged (hit 0.3 / kill 2 / received −0.2 / death −1 / win 2), `shot_cost` removed; (N0, k, M) = f(progress) of the existing ADR controller (SpawnCurriculum), linear 30/20/60 → 8/5/16, thresholds ratio_high 0.10 / ratio_low 0.07; first run D frozen 250 (one variable); γ 0.995; no death or truncation at empty, starvation 30 s kept; proprio nb_shells / 60 (constant, not / current max). Code: ammo parameters via JoltEnemyTank constructor and the factory (public interface ⟹ Samuel validation), progress → ammo mapping in main/train_environment, model tests.
